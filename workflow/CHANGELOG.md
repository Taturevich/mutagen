# Change log

## 2026-11-14
- Mutation coverage probes now register site entry before evaluating the expression and publish probe files atomically. Missing or corrupt probe artifacts fail coverage collection instead of appearing as empty coverage.
- Mutation and site runtime indices are assigned deterministically without truncated-hash collisions, and stable external hashes are no longer truncated. Confirmed assertion kills stop further test execution for that mutant; nonzero test-runner exits without TRX-reported test failures remain infrastructure errors.
- Verified a warning-free .NET 11 solution build and a complete sample mutation run (13 candidates: 9 killed, 3 survived, 1 uncovered). Repository `build.cmd`/`test.cmd` entrypoints are absent in this checkout, so verification used `dotnet build` and the CLI directly.

## 2026-11-14
- Migrated all four solution projects to `net11.0`, pinned the SDK to 11.0.100, and updated the mutation engine's test assembly lookup for `net11.0`.
- Updated direct NuGet dependencies to current stable releases: Microsoft.CodeAnalysis.CSharp 5.12.0, Microsoft.NET.Test.Sdk 18.12.0, NUnit 5.0.0, and NUnit3TestAdapter 6.3.1.
- Verified restore, a warning-free solution build, and all 8 sample tests on .NET 11. Ran three four-worker mutation samples and three four-session Stryker.NET 5.1.0 runs on the same sample. Both reported 75% mutation score. MutationFramework produced 13 candidates (9 killed, 3 survived, 1 uncovered); Stryker produced 17 (12 killed, 3 survived, 1 ignored, 1 uncovered).
- Median elapsed time was 40.755 s for MutationFramework (range 39.944–41.094 s) and 26.845 s for Stryker (range 26.819–27.209 s), with Stryker 34.1% faster in this small sample. Candidate counts and mutation operators differ, so the equal scores do not imply equivalent coverage or a general performance ranking. Per-run reports are under `artifacts/benchmark/`.

## 2026-11-14 — Mutation engine execution and correctness update
- Added supported VSTest TranslationLayer discovery and persistent runner-controller sessions. Discovery returns structured test case identities, including parameterized case IDs. Baseline collection now executes exact cases with a fresh testhost each time; mutation workers reuse their controller but retain a fresh host per case and process-scoped activation.
- Added plan-only and candidate/test discovery phases, all configured test project handling, compact integer probe storage, semantic exclusions for unsupported expression shapes, explicit missing/corrupt coverage errors, outcome diagnostics, execution counters, and separate coverage/probe timing. The HTML report now exposes exclusive phases and execution counters.
- Added NUnit engine integration coverage and a 200-mutant/100-case real scale fixture. Full solution build completed with zero warnings/errors; solution tests include 100 scale tests, 15 sample tests, and 5 engine integration tests. SDK sample passed with 18 candidates (10 killed, 7 survived, 1 uncovered).
- On the same 13-candidate sample and machine, three-run medians changed from 66.336/47.515/43.134 s to 21.658/17.334/17.116 s at 1/2/4 workers (60.3–67.4% lower wall time). Outcomes remained 9 killed, 3 survived, 1 uncovered. The old implementation launched 27 test-runner processes by derived test invocation counts; the new implementation observed 30/31/33 total engine/controller/testhost starts, including 26 testhosts, while using only 2/3/5 persistent controllers and reducing mutation test executions from 20 to 17 through early confirmed-kill termination. Detailed measurements and counting definitions are in `benchmarks/mutation-engine-comparison.json`.
- One four-worker scale run completed 200 mutants and 100 tests in 156.971 s (100 killed, 100 survived), with 408 observed starts and 5 persistent controllers. Peak memory was not measured. This scale result has no same-fixture original-engine comparison.
- Implemented deterministic conflict-graph batches, bounded load-balanced work units, exact test-to-mutant maps, and `isolated`/`batched`/`auto` modes. Full mode equivalence passed. Batched runs remain explicit because the final timing matrix shows no repeatable wall-time gain and the testhost count is unchanged.
